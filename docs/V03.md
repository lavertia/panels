# Lavertia v0.3 alpha — Modular Navigation and Dashboard Widgets

This milestone adds the foundation for Filament-inspired Panel navigation and dashboard Widgets **without a Filament dependency**. Laravel + Inertia remain the host application. The Component Protocol v1 is unchanged; the Page response gains optional `lavertia.navigation` metadata.

## Register a Panel

```php
use Lavertia\Panels\Navigation\NavigationItem;
use Lavertia\Panels\Pages\DashboardPage;

return [
    'panels' => [
        'admin' => [
            'path' => 'admin',
            'middleware' => ['web', 'auth'],
            'pages' => [DashboardPage::class],
            'navigation' => [
                NavigationItem::make('dashboard', 'Dashboard')->sort(0),
            ],
            'dashboard_widgets' => [],
            'discover_widgets' => [],
        ],
    ],
];
```

`DashboardPage` is opt-in. If a custom Page already owns the `dashboard` slug, do not register both. An existing Dashboard Page can include `app(PanelRegistry::class)->dashboardComponents('admin')` within its own component list instead.

## Register a module

An InterNACHI/modular or ordinary Composer-backed module can register Pages, navigation and Widgets from its Service Provider:

```php
namespace Modules\Inventory\Providers;

use Illuminate\Support\ServiceProvider;
use Lavertia\Panels\Navigation\NavigationItem;
use Lavertia\Panels\PanelRegistry;

final class InventoryServiceProvider extends ServiceProvider
{
    public function boot(PanelRegistry $panels): void
    {
        $panels->discoverPages(
            panelId: 'admin',
            in: dirname(__DIR__).'/Lavertia/Pages',
            for: 'Modules\\Inventory\\Lavertia\\Pages',
        );

        $panels->discoverWidgets(
            panelId: 'admin',
            in: dirname(__DIR__).'/Lavertia/Widgets',
            for: 'Modules\\Inventory\\Lavertia\\Widgets',
        );

        $panels->navigationItem(
            panelId: 'admin',
            item: NavigationItem::make('inventory/overview', 'Inventory')
                ->group('Operations')
                ->sort(20)
                ->ability('inventory.view'),
        );
    }
}
```

The host application must define the `inventory.view` Gate, enforce tenant-scoped queries and set suitable Panel middleware. A hidden link is not route authorization. The NavigationItem links only to an actual registered Lavertia Page in that specific Panel, not an arbitrary URL.

## Implement a Widget

```php
<?php

declare(strict_types=1);

namespace Modules\Inventory\Lavertia\Widgets;

use Lavertia\Panels\Components\Stat;
use Lavertia\Panels\Components\StatsGrid;
use Lavertia\Panels\Widgets\DashboardWidget;

final class StockOverview extends DashboardWidget
{
    public static function sort(): int
    {
        return 20;
    }

    public function canView(): bool
    {
        return auth()->user()?->can('inventory.view') === true;
    }

    protected function components(): array
    {
        return [StatsGrid::make([Stat::make('Items', 12)])];
    }
}
```

Widgets are resolved through Laravel's container on every dashboard request. Their `canView()` is checked before components are constructed; any Eloquent queries must also enforce Policies and tenant isolation. Module Widgets can also be registered explicitly using `$panels->dashboardWidget('admin', StockOverview::class)`, or placed in `dashboard_widgets` config.

Duplicate Widget classes are deduplicated and sorted by `::sort()` and class name. Recursively discovered abstract classes, non-Widgets, and missing optional module directories are ignored. Navigation items with identical configurations can be registered repeatedly; conflicting items for the same slug are rejected.

## Payload and frontend support

Each Page may emit `lavertia.navigation` as a list of `{slug,label,group,url,active}` objects. Only actual, registered Page routes from the active Panel may appear; Laravel Gate abilities are checked for every request. Navigation remains available after route caching.

The React, Vue and Svelte adapters use Inertia Links, focus-visible styles and `aria-current="page"` in responsive, RTL-aware navigation landmarks. Pages with no navigation keep the existing layout.

## Verify

```bash
composer dump-autoload
php artisan optimize:clear
php artisan route:list --path=admin
php artisan route:cache
php artisan test
npm run dev
```

CI installs a real Laravel 13 + InterNACHI/modular Inventory module, verifies auth, navigation, Widgets and route caching. The three Starter Kits must pass TypeScript and production builds.

This PR implements navigation and dashboard Widget foundations. Full Resources, Relation Managers, Panel-specific login UI and stable version tags are **not included**.
